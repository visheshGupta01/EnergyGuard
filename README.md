# EnergyGuard AI

An academic machine-learning application for **household electricity consumption forecasting, unusual-pattern detection, and theft-risk screening**.

> Theft-risk output is a screening signal only. It is not proof of theft and must never be used for automatic disconnection or enforcement.

## Project scope

| Capability | Dataset | Model | Output |
|---|---|---|---|
| Next-hour consumption forecasting | UCI Individual Household Electric Power Consumption | Linear Regression, Random Forest Regressor | Predicted hourly kWh |
| Unusual consumption detection | UCI household data | Isolation Forest | Unusual observations and anomaly scores |
| Theft-risk screening | SGCC Electricity Theft Detection | Random Forest Classifier | Class probability and risk indicator |

The datasets remain separate. UCI data represents one household in Sceaux, France (Dec 2006–Nov 2010); SGCC data represents Chinese utility consumers. Results should not be assumed to generalise to Indian consumers.

## 1. Setup

Python 3.10 or newer is recommended.

```bash
git clone https://github.com/visheshGupta01/EnergyGuard.git
cd EnergyGuard
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## 2. Download and place datasets

### UCI household dataset

Download the **Individual Household Electric Power Consumption** dataset from:
https://archive.ics.uci.edu/dataset/235/individual+household+electric+power+consumption

Extract the file and place it at:

`data/raw/household_power_consumption.txt`

The pipeline accepts the original semicolon-separated UCI text file.

### SGCC theft detection dataset

Use the dataset and extraction instructions from:
https://github.com/henryRDlab/ElectricityTheftDetection

The upstream repository instructs users to download its split archive parts together and extract them as one archive. Place the extracted consumer-level CSV at:

`data/raw/sgcc.csv`

Expected columns: `CONS_NO`, `FLAG`, and daily consumption columns. The code detects daily columns, sorts them by date where possible, and does not use `CONS_NO` as a predictive feature.

**Dataset files are not included in this repository.** They are large and have separate source terms. Do not upload private or restricted data.

## 3. Run the data audit and training pipeline

From the repository root:

```bash
python -m src.data_pipeline
python -m src.train --all
```

Or train individual tasks:

```bash
python -m src.train --forecast
python -m src.train --anomaly
python -m src.train --theft
```

The scripts create processed datasets, fitted pipelines/models, metrics JSON, and evaluation plots under `data/processed/`, `models/`, and `reports/`.

### Pipeline design

- UCI: parse date/time, treat `?` and blanks as missing, interpolate only short internal gaps (up to 3 minutes), retain valid zero readings, and aggregate minute-average kW to hourly kWh.
- An hour is retained only when it has at least 54 valid minute readings (90% initial quality threshold).
- Forecasting features use lagged hourly consumption, rolling means, hour, and weekday. The target is the following hour.
- UCI train/validation/test partitions are chronological.
- SGCC: daily columns are ordered chronologically; short internal gaps are interpolated; remaining missing values are imputed using a median imputer fitted on training consumers only.
- SGCC splits are consumer-level and stratified. `FLAG` is never imputed and identifiers are never used as features.
- Class imbalance is handled with class weighting. No resampling is applied to validation or test data.

## 4. Launch the dashboard

After training:

```bash
streamlit run app.py
```

The dashboard provides an overview, next-hour forecasting, unusual-observation review, theft-risk screening, and evaluation metrics. Some pages remain in a clear setup state until their corresponding dataset/model has been trained.

## Evaluation

- Forecasting: MAE, RMSE and R² on a later held-out time period, plus actual-vs-predicted plot.
- Theft classification: precision, recall, F1, PR-AUC, confusion matrix and class-wise report. Accuracy alone is not sufficient for the imbalanced SGCC target.
- Anomaly detection: count/percentage flagged, anomaly scores and representative timestamps. UCI has no ground-truth anomaly labels, so supervised precision/recall are not reported.

## Important limitations

1. UCI contains one household in France; it is a method demonstration, not a population-level forecasting study.
2. SGCC is Chinese utility data; its patterns may not generalise to Indian consumers or other meter conditions.
3. Missingness and class imbalance in SGCC can affect results. Review the generated audit and metrics.
4. Isolation Forest flags unusual patterns, not theft.
5. False positives can unfairly affect consumers. Any real-world concern requires independent technical and physical investigation.
